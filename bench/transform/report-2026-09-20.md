# bench transform: 2026-09-20

Machine: DESKTOP-AHUN9RO.

**No measurement in this report is rerun and no model call was made to write it.** `bench/transform` compares the write tool against a typed-edit tool by arithmetic over token estimates fitted to real recorded steps; it never calls a model. The census below (14 writes, 17 turns, 11 creates, 3 replaces, 0 refusals) is the same result BOJI-086/BOJI-090 recorded when this corpus was first measured, restated on its own line, and reproduced today by the package's own existing test against the same committed fixture.

## The set

`bench/transform/testdata/sessions`: 17 recorded turns from real sessions, copied into testdata because `.boji` is excluded from the tree. `bench/transform/testdata/before`: the pre-edit state of the two files those turns wrote to that already existed.

## From BOJI-090's log, taken from a ticket log rather than a rerun

Of 14 write calls in 17 turns, 11 create a file that did not exist, where a typed edit cannot help by construction. The three that changed an existing file were on files of 9 and 11 lines. One line changed in the largest recorded file costs 4,284 output tokens to rewrite and 96 to express with the typed set, 45 times less. The saving is real and this corpus has almost no instance of it: only 3 of 14 writes are the shape the typed set exists for.

14 writes, 11 creates, 3 replaces, 0 refusals, and the 4,284-versus-96 figure all match BOJI-090's log exactly. This run made no model call and is deterministic: it reproduces the existing numbers rather than refreshing them.

On the whole corpus the typed arm spends 3.7% more output than the write arm, because 11 of 14 writes are creates the typed set cannot help with and the typed envelope's own overhead outweighs what it saves on the 3 replaces. On the one large single-line edit the typed arm wins by 45 times. The corpus mostly does not exercise the case the mechanism is for.
