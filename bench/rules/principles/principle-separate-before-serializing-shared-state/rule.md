Rule: when concurrent actors might write the same file, key or object, first ask whether they need one shared object at all. If they publish independent facts, give each actor its own file, key or collection and merge only where the result is read. Only when one shared write target is a real invariant, serialize access structurally, with a file lock, a single writer or an atomic compare and swap; a comment or a convention is not concurrency control, and an in-process mutex does not protect a file two processes write.
