# bench minimal: tofu on one vCPU and 128 MB, against the rivals

**tofu finishes every rung, 0 to 10 sub-agents, under one vCPU at 256 MB and at 128 MB, on a Linux cgroup and a Windows job object. Claude Code and omp do not start under either limit; codex finishes 0 and 1 sub-agents at 256 MB and dies at 4, and dies at 0 under 128 MB.**

A sub-agent costs tofu about 0.7 MB of private memory, 1.8 goroutines and 18 ms of CPU. The floor is tofu's own binary, not its sub-agents.

## tofu under a cgroup, one vCPU, read arm, 0 / 1 / 4 / 10 sub-agents

| limit | peak MB | private MB | RSS MB | CPU s | wall s | goroutines peak | finished |
|---|---|---|---|---|---|---|---|
| 256 MB | 57.4 / 59.5 / 62.0 / 65.3 | 9.5 / 10.9 / 13.3 / 16.4 | 31.3 / 37.0 / 36.1 / 39.2 | 0.10 / 0.27 / 0.20 / 0.28 | 0.2 / 0.5 / 0.4 / 0.5 | 16 / 16 / 20 / 34 | all |
| 128 MB | 58.1 / 59.6 / 60.9 / 64.9 | 9.4 / 10.8 / 12.2 / 15.8 | 31.5 / 35.0 / 34.4 / 37.9 | 0.10 / 0.13 / 0.21 / 0.28 | 0.2 / 0.3 / 0.4 / 0.5 | 15 / 17 / 22 / 35 | all |

tofu serve idle for 20 s: peak 50.7 MB, private 4.2 MB, RSS 26.0 MB, 0.23 s of CPU, 16 goroutines, at both limits.

## The rivals under the same Windows job object, live

| tool | 256 MB | 128 MB | how it ended |
|---|---|---|---|
| tofu | every rung | every rung | finished |
| Claude Code 2.1.300 | does not start | does not start | exit 0xC0000409 at 254 MB of commit |
| omp 18.3.2 | does not start | does not start | bun: OutOfMemory reading cli.js |
| codex-cli 0.155.1 | 0 and 1 sub-agents, dies at 4 | dies at 0 | memory allocation of 33554432 bytes failed |

tofu ran on a cassette and the rivals live, so only whether a tool starts and finishes compares, not wall or CPU.

## How low tofu goes, cgroup, read arm

| limit | 0 sub-agents | 10 sub-agents |
|---|---|---|
| 64 MB | 0.2 s | 0.6 s |
| 48 MB | 0.2 s | 5.9 s |
| 32 MB | 130.9 s | killed at 300 s |
| 24 MB | killed at 300 s | killed at 300 s |

Below 48 MB the kernel keeps evicting and rereading the 48 MB unstripped binary; private memory stays at 9 to 17 MB and nothing is killed for memory.

## What a sub-agent allocates (10 against 1, divided by 9)

| owner | allocated | where |
|---|---|---|

| the tool list marshalled into the session each request | 594 KB | internal/turn/row.go:590 into internal/session/exchange.go:57 |
| the sub-agent prompt, composed once | 352 KB | internal/turn/spawn.go:411 |

## Conditions

Source: TOFU-1374, 2026-10-14, tofu 0.5.14+dev from a git archive of 3827a25d with a goroutine counter overlaid (bench/minimal/overlay/profile.go; the plain binary differs by 0.5 to 1.6 MB). Linux: cgroup v2 in WSL2, memory.max with swap 0, cpu.max one CPU, page cache dropped before each run. Windows: a job object commit limit and affinity to one CPU. One run per row; differences under 1 MB or 0.1 s are noise. Rows: results.jsonl; `go run ./bench/minimal report results.jsonl` prints them all.
