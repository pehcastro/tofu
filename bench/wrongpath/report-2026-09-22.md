THE ANSWER

The measure cannot separate two arms and this line of work stops here.

The number that decides it: at 30 sessions per arm the smallest visible difference in
reverts is 1.01 per session, against a corpus mean of 0.47. An arm that removed every
revert in the corpus would move the mean by 0.47 and stay inside the noise. The same
holds for all five measures. The best of them, contradiction, needs 0.62 per session
against a mean of 0.44, still 1.4 times the whole quantity being measured.

The cause is not the detector. It is that 82 of 109 sessions carry no shape at all and
the totals sit in a handful of sessions: one session holds 17 of the 51 reverts and 7 of
the 48 contradictions. A count whose mass is in one session out of a hundred is a count
of that session, not of a prompt.

WHAT THE SHAPES MISS

Each of the five rows below names one false positive. The three the ticket asked for:

revert: a second pass over the same file is often a refactor. 137 of the 1,401 calls
write or edit anything, so the revert row is built on one tenth of the corpus, and in a
session that edits one file six times on purpose it counts five reverts.

re-read: re-reading a long file after twenty intervening calls is how a person works.
The detector cannot see whether the earlier result was still in context, and the corpus
records no compaction event per call, so a necessary re-read and a wasted one are the
same row.

contradiction: a failure is sometimes the answer that was asked for, and this repository
runs a convention of showing a test failing before showing it passing. Every one of those
is counted as a contradiction.

WHAT WOULD MAKE IT MEASURABLE, IF ANYBODY WANTS TO TRY AGAIN

Not more sessions. The shape is absent from three quarters of them, so ten times the
corpus buys a mean ten times better measured and still under one per session.

It would need a corpus of sessions that all write code, run on the same task, where the
count is per task rather than per session. That is bench/harness with a repeat count, not
the recorded corpus.

TWO ARITHMETICS FOR THE SAME QUESTION

The harness rule, taken from bench/harness/report.go, calls a difference smaller than the
widest spread no difference. Over 109 sessions the widest spread is one session's worst
case, so that rule demands 17 reverts per session and is useless at this corpus size. It
is reported because it is the rule the tree already applies, and because both arithmetics
give the same verdict.

The second is the detectable difference in two means: two standard errors of the
difference, 2 * sd * sqrt(2/n). It is the gentler of the two and it still refuses.
