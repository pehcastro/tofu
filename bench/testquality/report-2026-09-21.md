## The correction that comes first

**The three rules are structural `go/ast` walks**, `kind: structural`, in `internal/rule/claim.go` and `internal/rule/gotest.go`. No Jev call anywhere in them. The ticket that opened this work called them typed judgments over a diff and that was wrong. The pattern arm below therefore compares two deterministic checkers against each other, not a pattern against a model.

## The arm

Ten tasks, each run twice, rules on and rules off. The rules-off arm removes the rule text from the prompt and nothing else. One run is missing: t09 off hit a codex stream error after 7 steps. It is counted and named, and every total below is over the nine comparable tasks.

## The headline: the rules moved nothing

Dead-test count over the nine comparable tasks: **off 53, on 53.** Net zero. t01 improved by 2 with the rules on, t05 got worse by 2, and the other seven were identical between arms.

**The reason is the useful part.** 9 of 10 rules-off runs and 10 of 10 rules-on runs called `tofu_rules_check` on their own, unprompted, because it is a standing tool on every turn regardless of arm. The model already reaches for the rule catalog through the tool, so a sentence in the prompt changes almost nothing.

## Mutation, three packages

Scope was cut from ten packages to three, because ten runs at up to fifteen minutes each was three hours against a release. The three chosen are the only three of the nine comparable tasks where the two arms' files differed by any signal already measured. The other six produced dead-test-identical files, so a mutation run on them could only confirm a null result a cheaper proxy had already given.

One worker at a time, no run over fifteen minutes, none needed killing.

**t01, `internal/judge/policy`.** Off 95.58 percent, 108 killed, 5 lived, 6 not covered. On 95.58 percent, the same four numbers. Byte identical. The dead-test count moved from 12 to 10 and the mutation score did not move at all: the two extra existential-claim functions the off-arm file carried were not adding or losing any kill.

**t02, `internal/judge/ledger`.** On 92.31 percent, 48 killed, 4 lived, 4 not covered. **Off could not be scored at all**: `go vet` fails it, `spend_test.go:49:4: result of (Unit).String call not used`, and gremlins refuses to gather coverage over a package that does not vet clean. Its mutation score is undefined rather than low.

**t05, `internal/judge/state`.** Off 77.34 percent, 99 killed, 29 lived, 33 not covered, 3 timed out. On 77.34 percent, the same four numbers. Byte identical again, and the dead-test count moved the other way this time, 10 to 12.

## Mutation and the dead-test count disagree, and that is the finding

Two of three measured tasks show the dead-test count moving while mutation held dead still. The third shows the dead-test count holding still, 9 against 9, while mutation caught something the count could not see in principle: **a file that does not vet, and therefore cannot be mutation-tested at all.**

A rule can only count a claim inside a file that parses and passes vet. So the dead-test proxy missed the sharpest divergence in the whole ablation, and `go vet`, which this project already runs everywhere, is what caught it.

## The pattern arm

For `test_assertion`: 36 tautological flags across 19 completed files, against the rule's 54. They diverge in both directions, with cases either way.

The rule catches `if result == 0` that the pattern misses, because the line contains a comparison operator. The pattern wrongly flags thirteen `require.Equal` shaped tests as tautological that the rule correctly reads as substantive. **This is the one clear positive result in the ablation**, and it is a result about two checkers rather than about a judgment.

## Per rule, and one deletion candidate

- `test_boundary_cases` moved 0 of 9 comparable tasks. That is the strongest null result this sample can produce and it is named as the deletion candidate.
- `test_mock_boundary` fired 0 times across all 19 files in both arms, because none of these ten packages had anything to mock. That is not evidence either way and it is not a deletion candidate on this run.
- `test_assertion` moved in 2 of 9 tasks and cancelled to net zero. Not a deletion candidate: the pattern arm above is where it earns its keep.

## What should block

**Nothing earned a blocking hook.** If one is written next, the number supports a logger over a block: run `tofu rules check` after every turn that touches a test file, so the one-in-ten gap in voluntary tool use stops being sampling noise.

## Reading it

```

```

The mutation runs are driven through `bench/testquality/mutrun`, a small command over `mutate.Gremlins`, which puts every child inside a Windows job object with a 4 GiB ceiling. Running `gremlins` by hand gets the run with no bound at all, which is how a mutation run once reached 30.6 GB on this machine.
