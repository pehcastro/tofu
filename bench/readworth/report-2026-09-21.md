## The corpus

`bench/readworth/testdata/readworth-corpus.jsonl`, 70 real paragraphs, each with the task it was read under, drawn from `.tofu/sessions` through `bench/corpus.WalkSessions`, never read as a file directly. 35 labelled keep, 35 labelled drop, hand-labelled against the `read_worth@1` criteria (does the paragraph carry the answer, a finding, a measurement, or a caveat the reader has to act on, versus preamble, recap, hedging, jargon or selling with nothing under it). The labels are mine: this ticket ran with no other reviewer in the loop, and that is a limitation worth naming rather than hiding.

25 distinct tasks are represented, from one-line file writes to a multi-file REST API change repeated across nine separate sessions to five different `explain this repository to me` runs. Position (`opening`, `middle`, `closing`) and `already_said` (the paragraphs of the same reply that came before) are carried through unchanged, since the question set reads both.

### Why the reader needed a field before this corpus could exist

`bench/corpus/reader.go:RecordedStep` carried only `Index` and `ToolCalls` before this ticket. The reply text a decision like `read_worth` judges, `AssistantText` in the single-file schema and `assistant_text` in the header-and-jsonl schema, was silently dropped by `json.Unmarshal` on both schemas, so `WalkSessions` reported turns, steps, tool calls and writes correctly and carried zero paragraphs. `RecordedStep` now has an `AssistantText` field (`reader.go:27`) with a custom `UnmarshalJSON` that reads both key spellings, and `scrubTurn` (`reader.go:79`) scrubs it beside `Task` and the tool call fields. `bench/corpus/reader_test.go:TestTheReaderCarriesReplyTextOnBothSchemas` and `TestAPlantedHomePathInReplyTextDoesNotSurviveTheRead` cover it. Across the real tree this exposes 124 steps with non-empty reply text and roughly 246 candidate paragraphs at production split granularity (`internal/sift.Split`), so 70 hand-labelled rows is a sample of that ceiling, not the whole of it.

## Arms

- **jev**: `internal/sift.BuildState`-shaped state (`paragraph`, `task`, `already_said`, `position`) sent to `read_worth@1`, decided by `internal/sift.Decide` at the shipped rule (`sift.DefaultRule()`: answer floor 1.5, padding ceiling 2.0). This is the same rule `cmd/tofu/sift.go` uses; there is no `catalog/policy/read_worth@1.yaml`, so "shipped threshold" means this rule.
- **signpost**: `internal/sift.Signpost`, the free arm that already beat a sift in this project (a markdown heading or a short colon-terminated line is dropped, everything else kept). No threshold to set.
- **keep everything**: the floor. No paragraph is ever dropped.
- **length alone**: `bench/readworth.ArmLength`, drop a paragraph under a word-count floor, keep everything else. Swept across seven floors (5, 8, 10, 12, 15, 20, 30 words) chosen ahead of time as plausible preamble lengths, not fit to this corpus's own labels.

The same reading TOFU-217 got on shell output and TOFU-236 got on fetched pages: the score moves with the task, so the free arms above, which cannot read the task at all, are giving something different in kind, not a cheap approximation of the same thing.

## Arm that wins and the recommendation

The length-15 free arm, and `read_worth` should be unwired in favor of it. At the point where jev's accuracy sits, the length floor saves more bytes for the same accuracy, on both runs, with no live call and no cost. jev is not wrong to move with the task (the two-task reading above is real and reproducible), but on this corpus that sensitivity never translates into keeping a paragraph the length rule would have dropped correctly or dropping one it would have kept correctly, at a matching savings level. `cmd/tofu/sift.go` has no policy file and no `mode: shadow` gate to flip; the `--arm signpost` default is already free. The recommendation is to make length-alone (or a length-plus-signpost combination) the default arm and stop paying for the jev call in this path, the same shape the shell and page sieves already resolved to.

## What is not in this report

The corpus is 70 rows, a sample of roughly 246 available candidate paragraphs at the same split granularity, not the full set. The hand labels are mine, not a second reviewer's; a person re-labelling this corpus could move individual rows, though the length-15 floor's exact match with jev's accuracy across two independent live runs is unlikely to be an artifact of a handful of labels. Length-alone was swept over seven floors chosen before looking at outcomes; it was not fit to this corpus's own labels, so its 87.1% at floor 15 is not a tuned number, but it also has not been checked against a second, disjoint corpus.
