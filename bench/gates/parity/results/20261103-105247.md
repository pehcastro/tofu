## Manual

Not offline. Each is driven by hand, with these steps, on both builds.

### 1. login claude-sub and codex-sub

OAuth against the vendor, which an offline run cannot answer

1. build both exes, then for each: set TOFU_CLAUDE_TOKEN_URL and TOFU_CODEX_TOKEN_URL to a local stub that answers the token exchange
2. tofu login llm claude-sub --paste with a mock code, in a home made fresh in the run, and the same for codex-sub
3. tofu login --status --json on both builds, diff after masking the token expiry
4. drive chat --source claude-sub and --source codex-sub on a cassette, both builds, diff

### 2. live sub turns

a real wire to the vendor

1. point TOFU_CLAUDE_BASE_URL and TOFU_CODEX_SOCKET_URL at a recording stub and run tofu run with the same task on both builds, diff the requests the stub saw
2. the orchestrator runs one real claude-sub session in the interface on the candidate build at the end

### 3. usage and quota

the vendor usage endpoints

1. stub the usage URLs, run tofu usage --json on both builds, diff
2. drive quota --quota inputs/quota.json is in the catalog and covers the footer and /status

### 4. openrouter, meta, typesafe and brave key check

each key check is a network call

1. openrouter and meta: point TOFU_OPENROUTER_API_URL and TOFU_META_BASE_URL at a stub answering 200, run tofu login llm openrouter and tofu login llm meta with a fake key on both builds, diff
2. typesafe and brave have no URL override, so only the refused path is in the catalog (login/typesafe key, login/brave key)

### 5. jev paths

every jev answer is a classifier call

1. start a local stub answering the jev wire and set TOFU_JUDGE_ENDPOINT to it with a fake key in a fresh home
2. run tofu judge, tofu check, tofu sift --arm jev, tofu run --gate enforce and drive with a gate ask on both builds, diff
3. the dry runs and the no-key answers are in the catalog (judge/dry run, judge/no key, check/no key, sift/jev no key, run/gate enforce without a classifier)

### 6. learn scan model step

the scan calls a model and has no cassette path

1. run tofu learn on a fixed project on both builds with a live key, compare the proposals by hand

### 7. browser and chrome extension host

Chrome and HKCU are the person's own

1. start a fake relay on HOME/.tofu/browser/relay.sock as cmd/tofu/browser_test.go does
2. run tofu browser tabs, read, observe, click, open, close and batch on both builds against it, diff
3. never run browser install, uninstall or profile login against the real machine

### 8. drive desk and flows 12 to 14

tofu-desktop renders pixels

1. run tofu serve --stdio --cassette with the desk core cassettes on both builds and diff the transcripts; the serve catalog already covers every method
2. render the desk on both builds and compare screenshots by eye

### 9. update install, models reload and query.update

the release and model registries are on the network

1. serve a copy of the release json on a local port, set TOFU_UPDATE_API and TOFU_UPDATE_TARGET to a scratch copy of the exe, run tofu update on both builds, diff
2. set TOFU_MODELS_REGISTRY_URL to a local copy of the registry, run tofu models reload --json on both builds, diff after sorting the provider rows

### 10. ctrl+g editor and the clipboard

ctrl+g opens EDITOR and /copy writes the person's clipboard

1. set EDITOR to a script that appends a line to its file, drive ctrl+g by hand in a terminal on both builds, compare the composer
2. paste is in the catalog through drive --clipboard (drive/flow 10-steer-image)

## Unreachable

| item | why |
|---|---|
| models/reload | the providers it fetches fail in the order they finish, so two runs of one build print them in a different order |
| flows 4, 6, 7 and 9 | bench/flows seams them inside its own runner (a panic hook, a cap, a fold cassette built at run time, a survive kill), so a script alone does not replay them; bench/flows itself runs them |
| slash /copy, /copy-call and /quote | tofu drive leaves the app's Copy unset, so the app writes the real Windows clipboard; the hook needed is a Copy sink in cmd/tofu/drive.go beside the --clipboard reader |
| serve session.history right after turn.completed | one build answers from the live event lines (turn.started first, 14 lines) or from the persisted log (session.updated first, 6 lines) depending on timing, so two runs of one build differ; session-history-empty covers the method |
| gate ask keys 1 to 3 | the ask card only shows after jev answers ask, and no offline classifier exists; needs a TOFU_JUDGE_ENDPOINT stub |
| ctrl+g editor | it opens EDITOR in a terminal that drive does not have |
| tofu with no arguments, tofu --profile and tofu --temporary-project in a terminal | the app needs a real terminal; without one the catalog covers the refusal (app/no terminal and the rest), and drive covers the app itself |
| --profile output | verbs.md section 4 says profiles are not diffed, and the profile is timing |
| browser install, uninstall, profile new, login, stop and remove | they write HKCU or start Chrome on the person's machine |
| browser tabs, read, observe, click, fill, select, press, scroll, back, open, close, batch, build, bench, motion | they talk to the person's real Chrome through the relay |
| update without --check | it replaces the installed exe |
| learn | the scan step calls a model with no cassette path |
