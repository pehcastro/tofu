## Where the time went

| cause | share of samples | fix |
|---|---|---|
| Store.Tickets read 1,500 files one at a time | about 42% in syscalls | 8 readers into indexed slots |
| readSections appended each line to the section string | 15 to 17% | sections cut by offset |
| the TicketFiles sort ran the id regexp twice per comparison | 7% | each ref parsed once before the sort |
| report decoded 24,390 events on one goroutine | 19% | events read beside the tickets and decoded by the same 8 readers |

## Conditions

- Board: generated board BENCH, 1,500 tickets with logs, 24,390 events, seed 1356, a fresh home per run. No real ticket, no network, no model.
- Machine: DESKTOP-AHUN9RO, windows/amd64, 32 cpu.
- Warm-up: in the TOFU-1356 run the first read of just-written files took 11.2 s (likely a virus scan); it ran uncounted and is printed in the run header.
- Spread: an earlier TOFU-1358 run under heavier load gave report 1.47x and catchup 1.43x. In TOFU-1359 list and catchup were 1.9 and 0.35 ms slower at p50; round 1 of the same path gave 0.99x and 1.02x.
- The two tables are separate runs with separate heads, so their ratios are not multiplied.
- Correctness: on a broken board (missing front matter, a doubled section, a misnamed file, a cut event line, a 17 MB line, an empty line) head and fix print byte-identical stdout and stderr with the same exit code.
